# AIRPAD 手势与操控指南

本文档描述**实际实现**的判定逻辑与默认阈值。数值可在 `airpad/config.py`（profile 默认值）、`airpad/geometry.py`（伸指分数与质量门控）、`airpad/core.py`（状态机）中核对。

> 掌尺度（scale）= 0.5 ×（食指根→小指根距离 + 手腕→中指根距离），已按图像宽高比校正。下文所有"位移"和"捏合距离"都以掌尺度为单位，因此与你在镜头前的远近无关。

---

## 0. 设计原则：这是用来控制电脑的

- **启动即接管**：程序打开相机后直接进入桌面控制，不需要先"启用"或做一套武装手势。
- **手出现就控制，手离开就释放**：识别到可用姿势即接管指针；手离开画面、握拳、或质量不合格立即释放，不会补点击。
- **开掌是唯一的"放手"动作**：想重新摆放手的位置而不移动光标，就张开手掌。
- **一切失败都朝释放的方向**：识别不确定时释放，而不是猜。

安全出口：界面 **Pause**、窗口内 `Esc`、全局 **`Ctrl + Alt + Space`**。

---

## 1. 手放在哪里

| 要求 | 判定 | 不满足时界面提示 |
|---|---|---|
| 21 个关键点有效 | 无缺失、无非有限值 | `Missing landmarks` / `Invalid coordinates` |
| 手大致在画面内 | 最多 6 个关键点可越界 10%；但任何一个越界 35% 就拒绝 | `Keep the whole hand in view` |
| 距离合适 | 掌尺度在 0.015–1.2 之间 | `Hand too small or too close` |
| 手身份稳定 | 位置跳变 > 0.35 或两手距离差 < 0.04 | `Tracking changed - open your palm` / `Ambiguous hands` |
| 有明确姿势 | 食指处于伸展状态（见 §3） | `Make a pointing or open hand` |

> 与早期版本相比：边距从"任何一点越界 ±3% 就整帧丢弃"改成**容忍少量越界**（网摄像头常在显示器下方，手腕探出画面是常态）；去掉了"掌宽/掌高比"的硬拒绝。

**画面里有两只手时**：不再直接拒绝。会选择**食指伸展分数更高**的那只手（即正在指点的那只）并锁定它；只有当两只手看起来几乎一样（分数差 <0.08）时才提示 `Both hands look alike - show one hand`。所以另一只手随便放在画面里不会让指针失效。

想指定主手，在 Settings 里把 `Hand` 设为 Left / Right（默认 Auto）。

## 2. 接管与释放（不需要武装）

**接管**：只要食指处于伸展状态（见 §3 的分数判定），**下一帧就接管指针**，同时把运动基线归零——所以接管瞬间光标不会跳。

**从开掌回到指针约需 0.13 秒**：这是滞回的必然结果——开掌时四指都是"伸展"，收回食指后，另外三指需要约 4 帧才退出伸展状态（分数掉到 0.30 以下时按 −0.30/帧衰减）。在这几帧里姿势仍读作 `open`（保持 Clutch），所以在快速"开掌→再指"的循环里会感到一点点迟滞。这是刻意的：反过来做（让姿势立刻变成 `pointer`）会在你张开手的过程中就开始移动光标。

**释放**：以下任一情况立即释放全部输入：

- 手离开画面，或观测超过 80 ms 未更新（界面提示 `Tracking delayed - open palm to resume`）
- 握拳（五指全部收起）—— 界面提示 `Make a pointing or open hand`
- 张开手掌（Clutch，见 §4）
- 几何质量不合格、手身份歧义
- 按 Pause / `Esc` / 急停
- 相机故障、输入进程异常

**短暂卡顿不会关掉控制**：如果某一帧太旧导致输入批次被拒，程序只释放这一次的输入并提示 `Frames too slow - input paused, resumes automatically`，下一帧恢复跟踪就自动继续——不需要你手动再点 Enable。安全性由输入进程自己的 80 ms 观测上限与 150 ms 租约保证，不依赖 UI 层是否"关掉会话"。输入进程首次握手失败也会重试 3 次，而不是直接报"不可用"。

释放后**不会**补一次点击，也不会恢复旧的拖拽。

## 3. 手指伸展分数（识别的地基）

每根手指有一个 **0–1 的连续伸展分数**，不是"角度够不够"的硬判定：

- **其余四指**：指尖相对手腕的距离比上 DIP、PIP 两个指节（越伸越远），加上手指的直线度（指根到指尖的弦长 ÷ 三节指骨长度和）
- **拇指**：指尖离掌心的距离、指尖/指节距离比、离食指根的横向间距、直线度——四项加权

判定阈值：

| 用途 | 分数 | 说明 |
|---|---|---|
| 单次判定"伸直" | ≥ 0.50 | 无状态场合（回放首帧、单帧工具） |
| 进入滞回（出现） | ≥ 0.62 | 稳定度 +0.36/帧，累积到 0.62 才算"伸展" |
| 放松的指（0.45~0.62） | 未伸展 +0.20/帧；已伸展 −0.06/帧 | 约 4 帧（0.13 s）接管；已伸展时缓慢退出，不抖 |
| 模糊（0.30~0.45） | −0.10/帧 | 防止在阈值附近来回翻转 |
| 明确蜷起（<0.30） | −0.30/帧 | 约 4 帧退出伸展状态 |
| 两指/三指专用 | 中指（或无名指）≥ **0.75** | 半伸的中指**不会**把指针变成滚动 |

**为什么这么做**：早期版本用关节内角（`pip>150° 且 dip>135°`）硬判定，真手稍微弯曲、有噪声、或手指朝向镜头时就会被判成"未伸直"，姿势变成 `unknown`，直接导致完全无法控制。连续分数 + 滞回对噪声、远近、手型、旋转都宽容得多。

**合成测试容差**（`tests/test_geometry_robustness.py`）：脚本化姿势覆盖关键点抖动、±40° 面内旋转、透视压缩和掌尺度变化。这些是几何算法回归，不能推出真人识别成功率。

## 4. 姿势与对应动作

| 姿势 | 判定 | 动作 |
|---|---|---|
| `open` 开掌 | **四指全部伸展**（拇指不要求） | **Clutch**：立即释放并重建基线 |
| `pointer` 指针 | 食指伸展、中指未进入滞回 | 相对指针（食指移动 → 光标移动） |
| `two` 两指 | 食指+中指伸展（中指 ≥0.75），无名指/小指收起 | **默认仍是指针**；只有打开 Settings 里的 `Two-finger scrolling · experimental` 才变成滚动 |
| `three` 三指 | 食指+中指+无名指伸展（无名指 ≥0.75）且已开启 | Task View / 切换桌面 |
| 握拳 / 其他 | —— | 释放并回到 Clutch |

> **为什么开掌不要求拇指**：人张开手掌时拇指常常并拢贴在掌侧（实测这种姿势的拇指分数只有 0.48，远低于阈值），而拇指本来就是最不可靠的关键点。若要求拇指，Clutch 会静默失效——你想松手，光标却继续动。

> 两指滚动为什么默认关闭：**"用直一点的中指指着屏幕"和"两指准备滚动"在几何上是同一个姿势**（合成模型里两者完全相同）。如果默认开启，很多人一抬手就会把指针冻住。所以默认规则是"只要食指伸着就是指针"，滚动需要你显式打开。

**Clutch 的用法**：手举酸了、想换姿势、想够到屏幕另一角——先**张开手掌**，移动手，再收回食指。张开手掌的瞬间输入就释放了，所以这个过程中光标不会乱跑。

## 5. 相对指针

- 只有 `TRACKING` 状态下的**食指指尖**位移会产生光标移动
- 位移经 **One Euro 滤波**：静止时强平滑（截止频率 = `smoothing`，默认 1.5 Hz），快速移动时自动降低平滑，兼顾稳定与跟手
- 平滑后有径向停稳区：低速基础半径 0.008 掌尺度，随移动速度缩小；小幅往返抖动停住，持续微调累计出区后仍会移动
- 保留亚像素残差，因此**极慢的微动不会被逐帧取整吞掉**
- 灵敏度默认 1000 counts / 掌尺度，可在 Settings 调整或由校准推导

保护机制（触发即清零基线、输出 0 位移）：帧间隔 ≤0 或 >200 ms、掌尺度 <0.015、瞬时速度 >12 掌尺度/s（甩手）、坐标异常、观测过期。

## 6. Pinch 点击

```
   拇指尖与食指尖距离 / 掌尺度
        < 0.42（pinch_close）且 ≥3 帧、≥60 ms   → 确认闭合（有意为之的捏）
        期间触到 ≤ 0.25（pinch_contact）≥2 帧   → 才算真的指尖接触
        张开到 ≥ 0.78（pinch_open）            → 立即输出一次 click
        仅张开到 ≥ 0.62（pinch_release）        → 连续两帧后输出 click
        没有连续、同方向的越界掌位移            → 可以点击；单帧抖动和释放回弹不计入
```

**判定用的是原始 pinch 值，不是平滑后的值**：阈值来自未平滑的校准样本，重滤波会使边缘延迟、接触阈值不可达。抗噪采用连续帧、时间和阈值滞回：进入接触后允许 `0.08 × pinch_close` 的小回摆；进入闭合后允许 `0.05 × (pinch_release - pinch_close)` 的小回摆。清楚松开立即响应，仅模糊释放增加一帧确认。

一次点击要同时满足：

| 条件 | 默认值 | 挡掉什么 |
|---|---|---|
| 闭合持续 | ≥3 帧且 ≥60 ms | 单帧噪声、两帧掠过（挥手扫过时指尖偶尔靠近） |
| 接触深度 | 原始值进入 `≤ pinch_contact`（默认 0.252），在接触滞回区内持续 ≥2 帧 | 未进入接触的擦过和孤立尖峰 |
| 位移 | 未确认持续越过 `click_drag_travel`（默认 0.12 掌尺度）的掌位移 | 真正捏着走的拖拽；单帧尖峰、快速往返不算 |
| 姿势 | 必须由**伸出食指**的姿势发起 | **握拳**：握拳时拇指-食指间距同样很小，不加这条限制，"攥一下手暂停"会在张开时误点一下 |

> **接触深度不是一个固定常数，而是跟着你这个 profile 的 `pinch_close` 走**（`0.6 × close`）。它必须这样：如果一只手量出来的捏合尺度偏大（校准向导会把宽区间截断成 `pinch_close=0.60`），一个绝对的 0.25 可能**永远捏不到**，于是点击全部消失而界面毫无提示。改 `pinch_close` 时它会自动跟着变（除非你显式指定 `pinch_contact`）；旧 profile 缺这个字段时按它自己的 close 补齐。

- **松开时提交点击**：满足闭合、接触及位移条件后，达到个人 `pinch_open` 立即触发；只越过 `pinch_release` 时连续两帧后触发。0.8 s 的慢捏仍可点击。待决捏合超过 2 s 会取消，持续有效的拖拽不受这个上限约束。
- **捏合期间指针冻结**：进入 `PINCH_APPROACH`（拇指-食指距离单帧下降 >0.03）后位移立即停止累积，光标停在捏合开始的位置。所以点击落点＝你决定捏的那一刻的位置，捏的动作本身不会把光标带偏。
- **接近冻结不是噪声触发的**：需要"越过 0.70 且单帧下降 >0.03"才算收拢动作；在 0.68~0.70 附近抖 0.015 不会冻住指针。
- 未确认的 pinch（0.25 s 内没确认，或先超时）→ 取消，不产生任何点击
- 取消路径（超时 2 s、手丢失、握拳、开掌 Clutch、质量不合格）**一律不补点击**

> **阈值来源**：默认 `pinch_close=0.42` 与花绳（Cat Cradle Checker）原型验证过的 `0.42 × 腕-中指根距离` 同量级。早期版本用 `0.23`，等效只有它的一半，真手几乎捏不到——这是"用不了"的主因之一。
> `pinch_contact` 与另外三个阈值一样，**能从你自己的手量出来**（捏合相位的闭合分位与 close 之间取中点）：长指甲或关节粗的手捏不到很底，就用这只手自己的接触深度，而不是内置的 0.25。

双击 = 两次完整周期；中间清楚张开到 `pinch_open`（默认 0.78）只需一帧，仅到 `pinch_release` 则需两帧。

## 7. Pinch 保持 = 拖拽

确认闭合与指尖接触 → 保持 ≥`drag_hold`（默认 0.18 s）→ 掌位移 ≥`click_drag_travel`（默认 0.12 掌尺度），连续至少三帧、60 ms 且方向一致 → 输出一次 `left_down`。掌位置的三帧中位数也须越界，之后掌中心移动驱动拖拽；清楚张开立即 `left_up`，模糊释放需连续两帧。

- 点击和拖拽共用掌位移边界；较大的位移还需要持续方向证据、保持时间和接触确认。孤立一两帧的外移或来回抖动不再单独取消点击；未确认接触的扫过不会点击。
- 起拖至少保持 180 ms；Settings 可调整保持时间和起拖距离。指尖为了捏合而弯曲不会单独触发拖拽。
- 起拖瞬间重置运动基线，不会跳一下
- 拖拽中开掌、握拳、手离开画面、Pause、帧过期 → 立即 `left_up` + `release_all`
- 拖拽结束后**不会**补 click
- 有效跟踪中的拖拽不受待决捏合的 2 秒超时限制；新鲜帧、输入租约和急停仍然约束每次输入
- 丢失、取消或暂停后，旧的闭合捏合不能重新起拖或在松开时补点击；先分开拇指和食指，再开始下一次动作

## 8. 两指滚动、右键与缩放

主窗口“启用触控板手势”预设会开启两指滚动，关闭缩放和三指实验动作。两指稳定短停 120–400 ms，再收回单指，触发一次右键；两指移动后锁定滚动，退出不会补右键。开掌、未知姿势、丢失和过久停留取消右键意图。

滚动依据手掌平移，收中指时的指尖变化不会被算成滚动。练习区的网格和右键菜单可用于检查动作结果。

**先在 Settings 打开 `Two-finger scrolling · experimental`**，然后：食指+中指**明确**伸出（中指分数 ≥0.75）并保持 3 帧且 ≥0.08 s → 待定；再平移 ≥0.10 掌尺度 → 锁定为滚动。

- 同时输出垂直和水平位移分量；没有独立的主轴锁定策略
- 默认**自然方向**：两指上移 = 页面上滚，可在 Settings 关闭 `Natural scroll direction`
- 速度：默认 480 wheel 单位 / 掌尺度

**两指缩放 Zoom（同样是实验性，默认关闭）**：开启后张合幅度（对数比）≥0.12 且比平移证据强 1.5 倍才锁定缩放。分不清滚动和缩放就**关掉它**。

---

## 9. 三指动作（实验性，默认关闭）

打开 `Three-finger navigation · experimental` 后：三指并拢，0.12–0.65 s 内上移 ≥0.45 → Task View；左/右移 ≥0.45 → 切换桌面。一次滑动只触发一次，触发后锁定 0.6 s。

---

## 10. 暂停与急停

| 方式 | 范围 | 行为 |
|---|---|---|
| `Esc` | AIRPAD 窗口内 | 暂停控制 |
| 界面 **Pause** | — | 暂停控制 |
| 托盘 → Pause | — | 暂停控制 |
| **`Ctrl + Alt + Space`** | **全局**（任何程序前台时都有效） | 立即释放所有输入并暂停 |

急停热键由输入进程注册；注册失败时输入进程**不会进入就绪状态**，因此不存在"以为有急停其实没有"的状态。

## 11. 用不了的时候怎么查：手部诊断 + 按你的手定阈值

首次使用可直接双击 `Calibrate-AIRPAD.cmd`，或使用主窗口的校准按钮，完成开掌、握拳、指点、横扫与捏合五阶段测量。窗口会显示采集进度，并提供重试、取消和保存。

下面的命令行工具保留给开发诊断。运行 `--apply` 前退出使用同一数据目录的 AIRPAD，避免覆盖正在使用的设置：

```bat
.venv\Scripts\python.exe tools\hand_check.py            :: 只测量
.venv\Scripts\python.exe tools\hand_check.py --apply    :: 测量并写入 profile
```

它会引导你依次做五个动作，每个动作有 2.5~4 秒的采集窗口：

| 阶段 | 提示 | 用途 |
|---|---|---|
| 1 / 5 | 张开手掌，五指全部伸直 | 量出你"伸展"时的分数分布 |
| 2 / 5 | 握拳，五指全部收起 | 量出你"蜷起"时的分数分布 |
| 3 / 5 | 只伸食指，像指点屏幕 | 量出放松指点时食指的分数 |
| 4 / 5 | 在舒适范围内左右移动食指 | 量出你的**舒适移动范围 → 指针增益** |
| 5 / 5 | 拇指与食指反复捏合约 5 次 | 量出你自己的 pinch 张合区间 |

屏幕上同时实时显示：分辨率 / FPS / 推理耗时、几何门禁结果与**被拒绝的具体原因**、每根手指的**伸展分数**（带阈值条）、pinch 距离、分类出的姿势、状态机状态。

结束后写出 `artifacts/hand-check.json`，其中 `recommended` 给出：

- **每根手指的阈值**——放在你"伸展中位分"和"蜷起中位分"之间的空档（偏宽松一侧，因为漏判等于不能用，误判只是姿势变化）
- **每根手指的模糊区间起点**（`finger_marginals`）——锚定在**你自己蜷起中位数之上**。这一条很关键：如果只按阈值比例缩放，手分数偏低时蜷起的姿势会掉进模糊区间，几帧后也被判成"伸展"（一握拳反而开始指点）
- **指针增益**（`sensitivity`）——让你的**一次舒适横扫**对应约 1100 counts 的光标行程，与手的大小和离镜头远近无关。所以手小、坐得远的人不会得到一个"迟钝"的光标
- **pinch 三阈值**——从你捏合样本的 15%/85% 分位推导
- 每个相位的有效帧数；**任何相位少于 12 帧就会退回内置默认**并在 `defaults_used` 里列出

**哪些情况会拒绝自动改参数**（宁可不改，也不给你一个难用的设置）：

- 横扫幅度太小（10–90 分位跨度 <0.15 掌尺度）→ **不动增益**，`hint` 让你重做该相位。因为按公式会把增益顶到上限 2200，光标会变得极其敏感——比慢一点糟糕得多
- pinch 的张开/闭合分不开 → 不动 pinch 阈值
- 某根手指的两种姿势分不开 → 该指保留内置默认

**空档很窄也能用**：只要你的"伸展"和"蜷起"中位数差 ≥0.05，就会照常测并把阈值放在两者中点，同时在 `narrow_fingers` / `confidence: narrow` 里如实标注余量小——**不会**因为空档窄就悄悄退回那个不适合你的默认值。

`--apply` 会把结果写进 `runtime-data/profile.json`（`finger_thresholds` + `finger_marginals` + pinch 三阈值 + `calibrated: true`），下次启动即生效。没有 `--apply` 时它只测量、不动配置。再跑一次会覆盖上一次的测量结果。

> 为什么要这么做：固定的 0.62 是**对别人的手的猜测**。不同人的手指比例、MediaPipe 关键点精度、放松姿势都不一样。测一次自己的手，比反复调内置常数可靠得多。

**注意**：四个相位都需要手在画面里。若某个相位采到的帧太少，报告里的 `enough_data` 会是 false，`hint` 会**指名道姓**告诉你该重做哪一步：

| 情况 | `hint` 会说 |
|---|---|
| 某相位帧数不足 | `These phases collected too few frames: open, fist...` |
| 某根手指张合两种姿势分不开 | `No threshold could be measured for: index (the two postures are not separable...)` |
| 空档窄但能用 | `...the gap is narrow for: ring. They should work; re-run with a firmer fist...` |
| pinch 样本分不开 | `Your pinch samples did not separate, so the pinch thresholds were left unchanged.` |
| 一切正常 | `All four phases measured cleanly.` |

**程序也会主动提醒你**：如果画面里一直有手、但姿势连续 6 秒判不出来（这正是"阈值不适合你的手"的症状），界面会弹出提示让你跑 `hand_check.py --apply`；已经测过阈值的话，提示会改成让你重测。不会再出现"手在画面里、程序却一声不吭"的情况。

低帧率保护门槛是 1.5 s 内平均 <12 FPS 才释放（早期版本是 20 FPS，容易被误触发）。

## 12. 校准与调参

**校准**（`Guide me through calibration`）三步：开掌约 2 秒（≥45 帧）→ 食指左右移动约 3 秒（≥30 帧）→ 捏合/张开 5 次（≥60 帧）。校准会按你的实际张合分布推导灵敏度与 pinch 三个阈值；采样不足时会**拒绝**而不是写一份糟糕的 profile。

| 症状 | 调整 |
|---|---|
| 光标太慢/太窜 | Settings → Sensitivity |
| 静止时抖 | 提高 `smoothing` |
| 点击难触发 | 跑校准（会一并量出 `pinch_contact`）；或把 `pinch_close` 调大（更松）、`pinch_contact` 调大（更浅） |
| 误触点击多 | 把 `pinch_contact` 调小（要求捏得更实）；再把 `pinch_close` 调小 |
| 该点击却变成拖拽 | 把 `click_drag_travel` 调大（默认 0.12 掌尺度≈四十来像素） |
| 该拖拽却只点了一下 | 把 `click_drag_travel` 调小 |
| 捏不住、总是超时取消 | `pinch_confirm` 调小（默认 0.06 s，即 3 帧） |
| 想要滚动 | Settings → `Two-finger scrolling · experimental` |
| 滚动方向反了 | 关闭 `Natural scroll direction` |
| 老是"手不在画面内" | 手离镜头近一点，或把整只手放进画面 |
| 手指伸着却不响应 | 跑 `tools\hand_check.py`，看是分数不够还是被门禁拒绝 |
| 按住真实鼠标键时 AIRPAD 完全不动 | 这是设计：真实按键被按住时（你在用真鼠标拖东西）全部合成输入暂停，连光标移动都拒绝，避免和你的手动拖拽打架 |

## 13. 量一下你自己的准确率

```bat
.venv\Scripts\python.exe tools\click_eval.py --targets 100
```

练习模式（不接管桌面），依次给出 100 个目标。结束时 `artifacts/click-eval.json` 给出：召回、精确、误触数、误拖数、中位获取时间。规范要求的 MVP 门槛就是 100 次明确意图点击——**在此之前只能说"功能可用"，不能说"手感可用"**。
