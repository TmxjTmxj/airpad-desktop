# AIRPAD 隐私说明

AIRPAD 的设计前提是：**摄像头画面属于你的屏幕，不属于任何服务器。** 本文档逐项说明哪些数据在哪里处理、是否落盘、是否联网。

---

## 一句话总结

| 问题 | 答案 |
|---|---|
| 摄像头画面会离开这台电脑吗？ | **不会。** 全部在本地进程内处理，从不发送 |
| 画面会存到磁盘吗？ | **默认不会。** 显式截图命令会保存含预览区域的窗口图像，见下表 |
| 需要联网吗？ | 只有安装时下载模型那一次。运行期**不需要网络** |
| 会记录我在其他程序里做了什么吗？ | **不会。** 日志只记 AIRPAD 自身的状态与性能指标 |
| 会上传手势/关键点数据吗？ | **不会。** 没有任何上传路径 |

---

## 1. 摄像头数据

**处理链路**：相机 → Vision 子进程（镜像 → MediaPipe 推理）→ 通过容量为 1 的队列把**最新**结果交给主进程 → 主进程绘制预览与骨架。

- 原始帧只存在于内存中的队列里，容量为 1，新帧直接覆盖旧帧
- 主进程只在内存里做一次 `copy()` 用于画骨架，画完即被下一帧取代
- 普通运行不录视频、不保存图片或缓存帧序列；显式截图例外见下表
- 验证方式：`tools/camera_probe.py` 的输出里有 `"frames_saved": 0` 字段，且该工具只输出聚合指标（帧数、FPS、延迟分位数、最大手数）

**唯一的例外是你主动要求的**：

| 命令 | 行为 |
|---|---|
| `airpad run --screenshot <路径>` | 保存 **AIRPAD 自己的窗口**截图（含相机预览区域），路径由你指定 |
| `airpad replay <file.jsonl>` | 读取你提供的 landmark 文件；只读，不写帧 |
| `tools\integration_smoke.py --screenshot <路径>` | 同上，保存运行中的窗口截图；**画面里有手时会连手一起存下来** |
| `tools\replay_smoke.py` | 保存练习界面截图；背景是合成图，**不含任何相机内容** |
| `tools\click_eval.py --screenshot <路径>` | 保存评估窗口截图；只画目标与指针，**不含相机内容** |
| `tools\camera_probe.py` | 只输出聚合指标（帧数、FPS、延迟分位数），不写任何图像 |

请注意：**窗口截图会包含相机预览区域**，因此如果拍摄时有手在镜头前，那张 PNG 里就有你的手。这些命令都要求你显式给出输出路径或显式运行，程序不会自己截图。

预览画面只在你的屏幕上显示。关闭相机（`Stop camera`）后，Vision 子进程被有界地终止，相机设备随即被释放，其他程序可以立刻使用它。

## 2. 模型下载与网络

| 项 | 说明 |
|---|---|
| 下载时机 | **仅**在你显式执行 `airpad install-model` 时（`Setup-AIRPAD.cmd` 会调用一次） |
| 来源 | `storage.googleapis.com/mediapipe-models/…/hand_landmarker.task`（见 `airpad/resources.py`） |
| 大小上限 | 代码里硬限制 20 MB，超出即中止并删除临时文件 |
| 完整性 | 下载后校验 SHA-256，不匹配则**拒绝**该文件并报错 |
| 运行期 | 不下载、不检查更新、不发起任何网络请求；模型缺失时直接报错，不会静默联网补齐 |

模型指纹：

```
models/hand_landmarker.task
7,819,105 bytes
SHA-256 fbc2a30080c3c557093b5ddfc334698132eb341044ccee322ccf8bcf3607cde1
```

**关于依赖遥测**：本项目刻意锁定 MediaPipe 0.10.21 而非上游 1.x。在本机安装的 0.10.21 Python 包内检索 `telemetry` / `analytics` / `clearcut`，命中 **0 处**。这是"本机这份依赖没有可识别的遥测调用路径"的证据，不等于对全部二进制依赖的完整审计。

`airpad doctor` 只读取本机信息（Python 版本、已安装依赖版本、模型哈希），不联网。

## 3. 本地日志

日志位于数据目录（源码默认 `runtime-data/`，Windows EXE 默认 `%LOCALAPPDATA%/AIRPAD`，可用 `--data-dir` 或环境变量 `AIRPAD_DATA_DIR` 更改）：

```
runtime-data/
  airpad.lock          # 单实例锁（QLockFile）
  profile.json         # 你的设置（原子写入）
  logs/session.jsonl   # 结构化本地日志，2 MB 轮转 × 3 份
```

写入方式：所有日志经一个有界异步队列（上限 256 条）落盘，**磁盘慢或写满都不会阻塞控制环**；队列满时丢弃诊断而不是阻塞输入释放。

### 日志里到底有什么

每行是一个 JSON 对象，字段为 `time`（墙钟）、`event`，以及该事件专属的数值字段：

| `event` | 附带字段 |
|---|---|
| `enabled` | `practice` |
| `state` | 状态机状态名（如 `TRACKING`、`CLUTCH`） |
| `input` | `kind_name`（动作类型，如 `click`）、`practice` |
| `performance` | `fps`、`capture_fps`、`read_to_controller_ms`、`inference_ms` |
| `profile` | `revision` |
| `calibration_saved` | `revision` |
| `error` | `message` |

### 日志里没有什么

- ❌ 摄像头帧、帧的缩略图、任何图像数据
- ❌ 21 个关键点坐标、掌尺度、pinch 比例等生物特征量
- ❌ 你的键盘输入内容、其他程序的窗口标题、前台应用名
- ❌ 光标绝对坐标

日志记录的是动作发生的时间和类型，不是手部图像。你可以随时用文本编辑器打开查看；退出应用后删除所选数据目录，即可清空该目录中的本地状态。

## 4. 设置文件

`profile.json` 包含偏好和最终校准参数：灵敏度、平滑、滚动速度、pinch 阈值、五指阈值及滞回区间、主手、相机序号与后端、实验性开关、校准参考值与 revision。带 `schema_version`，字段白名单校验，使用临时文件 + fsync + `os.replace` 原子替换，减少不完整写入。

应用内校准的采样只保留在内存中，保存后写入最终参数。独立 `tools/hand_check.py` 会在显式运行时生成测量报告；请在分享前检查内容。源码包只包含白名单中的无相机演示图；Windows 包不包含 `artifacts`、个人配置或日志。

## 5. 输入注入的边界

AIRPAD 会向系统注入鼠标/键盘事件——这是它的功能。相关的约束：

- 只有 allowlist 中的动作类型可以被注入，其它字符串在进入 Win32 边界前就被拒绝
- 输入由独立 Broker 进程执行，UI 进程无法绕过租约直接注入
- 采纳**写前账本**：任何可能按下的键/按钮都先记录，再调用 SendInput，因此崩溃后可以据此补释放
- 暂停、丢失手、质量不合格、急停、超时，都会释放已按下的按键
- 不修改你的系统鼠标设置、不改变指针加速、不留下开机自启项

## 6. 你的控制权

| 你想做的事 | 怎么做 |
|---|---|
| 立即停止一切输入 | 按 `Ctrl + Alt + Space`（全局急停）或界面 `Pause` |
| 让 AIRPAD 完全不看摄像头 | 点 `Stop camera`，相机立即被释放 |
| 删除全部本地记录 | 退出后删除当前数据目录（源码 `runtime-data/`，EXE `%LOCALAPPDATA%/AIRPAD`） |
| 确认它没联网 | 安装完成后断开网络，程序功能不受影响 |
| 完全移除 | 退出后删除程序目录和使用过的数据目录；不安装服务或计划任务 |
