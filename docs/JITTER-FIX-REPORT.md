# 点击防抖修复（2026-09-27）

用户反馈：识别和指针移动已经可用，但手指晃动导致无法点击。本次保留识别几何、个人校准文件、灵敏度及手势开关，修复输入意图的判定。

## 查证的成熟方案

- [1€ Filter 作者的算法、实现和调参说明](https://gery.casiez.net/1euro/)：低速使用更强平滑，高速提高截止频率减少延迟。当前项目已有该算法，单纯再加大平滑会增加瞄准延迟；对捏合距离做重滤波还会使校准的原始阈值不可达。
- [Meta 官方间接交互最佳实践](https://developers.meta.com/horizon/design/indirect_interactions_bp/)：捏合本身会引起手部位移，导致指针离开小目标；建议使用其 Ray Interactor 抑制捏合抖动，并避免长响应延迟。其 SDK 面向 XR；本项目采用相同问题意识，在摄像头指针链路中实现停稳区、点击锁定和动作确认，并未接入 XR SDK。

## 根因与最终行为

旧逻辑记住原始手掌位置的最大偏移。任意单帧尖峰一旦超过起拖距离，就永久失去点击资格；保持时间达到后甚至会误起拖。起始帧自身带噪声也会污染整个手势的参考位置。接触和闭合的硬阈值又要求完全连续，临界抖动会反复清零。

1. **瞄准停稳区**：在原有 1€ 平滑后增加径向、带锚点的停稳区。低速基础半径 0.008 掌尺度，随平滑速度缩小。区域内指针停住；持续微移会累计到区域外再移动，快速移动仍响应。不会按每帧截掉小位移。
2. **点击期间保持目标**：捏合接近/保持阶段继续冻结指针。手指弯曲、孤立掌位置尖峰和快速往返不再单独取消点击。
3. **持续位移才起拖**：用最近三帧掌位置的逐轴中位数建立参考位置。超过个人起拖距离的原始位移须连续至少三帧、至少 60 ms，并与候选方向余弦相似度 ≥0.75；中位位置也必须越界。再满足接触及默认 180 ms 保持才按下左键。位移证据一旦确认，不会因回到原位而补点击。
4. **捏合阈值滞回**：仍在原始信号越过校准阈值后才进入闭合/接触。进入后，接触容忍 `0.08 × pinch_close` 的小幅回摆；闭合容忍 `0.05 × (pinch_release - pinch_close)` 的小幅回摆。未达到接触的擦过、孤立接触尖峰仍不会点击。
5. **释放边缘防抖**：达到 `pinch_open` 时立即提交点击/结束拖拽；仅越过 `pinch_release` 而未达到 `pinch_open` 时，需要连续两帧。30 fps 时多一个采样间隔，约 33 ms。真实丢失、开掌、急停仍立即取消/释放。

有意取舍：孤立一两帧的外移按抖动处理；明确拖拽需要持续位移。缓慢微调经过停稳区有少量起步距离。真实手感、摄像头噪声分布和真人点击成功率仍需使用实机确认，合成结果不能代替真人验收。

## 可复用教训

点击/拖拽不能由噪声信号的单帧最大值分流。应把原始校准阈值、状态滞回、连续意图证据和指针平滑各自处理；重滤波不能直接替代动作确认。回归不仅要覆盖干净手势，还要覆盖带噪声的起始帧和释放帧。
