# AIRPAD 操控体验修订 · 2026-09-26

用户反馈：识别已没问题，能移动光标，但操作手势不像触控板。保留既有识别算法和个人校准值，优先修复操作语义，不重新定标。

## 行为

- 指针照常由食指移动；捏合接近/确认期间冻结点击位置。
- 点击和拖拽使用同样的接触确认。只有持续捏住且手掌确实移动才起拖；指尖弯曲和张开本身不算拖动意图。
- 起拖至少保持约 180 ms；之后持续捏合的新鲜观测保持拖拽，松开或取消释放。取消后旧捏合不能重新起拖。
- 触控板预设：开启两指滚动，保持缩放和三指实验功能关闭。仅用户点击预设按钮时保存，原有手指识别和捏合阈值保持不变。
- 两指短停后收回为单指，可触发一次右键；两指移动后锁定滚动，结束不能再补右键。开掌、未知姿势、丢失或超时不能触发右键。
- 练习区明确区分左键、右键和滚动反馈，桌面模式与练习模式使用同一状态机。

## 交付与验证

- 用分离的指尖/手掌轨迹重现误起拖和释放误判；覆盖低帧率、抖动、连续点击、滚动/右键互斥以及释放账本。
- 基线 `pytest tests -q`：319 passed。源文件基线保存于 build/control-20260926-baseline。
- 修改后跑完整回归和合成端到端，再重新构建现有 Windows EXE，避免根启动器启动旧的二进制。
- 启动器让当前项目使用现有 runtime-data 配置；不复制、不改写个人校准值。便携包仍使用独立的默认数据目录。
- 真实手感需用户体验，测试不注入桌面、不打开摄像头。不会声称合成测试证明真人命中率。
